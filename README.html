一、先算清楚这笔账：你有什么，缺什么

转型不是清零重来。5 年 Android 经验里有大量可直接迁移的工程资产，精准识别它们能让你少走半年弯路。

可迁移的优势（你的本金）

  • 工程化能力：模块化、依赖注入、架构分层、CI/CD——AI 应用工程 80% 的工作就是这些
  • 产品化交付经验：把 Demo 做成稳定上线产品的能力，这是纯算法背景的人普遍缺失的
  • 性能与内存优化直觉：直接迁移到推理延迟、显存/内存占用、首 Token 时间优化
  • 异步与并发编程：Kotlin 协程 ≈ Python asyncio，流式响应、并发调用模型 API 天然上手
  • 移动端/边缘场景理解：端侧推理、离线降级、隐私合规——这是 2026 年最稀缺的方向
  • Kotlin/Java：Java 生态的 AI 栈（Spring AI、LangChain4j）是另一条低成本切入路径
结论：你缺的不是「编程能力」，而是「Python 生态 + LLM 原理 + AI 工程范式」这三块。

需要补齐的缺口（按优先级）

  • P0 · Python 生态：uv/poetry、类型注解、asyncio、pytest、FastAPI
  • P0 · LLM 应用范式：Prompt 工程、Function Calling、RAG、Agent、上下文工程
  • P1 · 模型原理够用即可：Transformer / Attention / Tokenizer / Embedding / 量化——懂原理，不必推导公式
  • P1 · 模型服务与评估：vLLM、推理部署、评测集、RAGAS、成本与延迟权衡
  • P2 · 微调：LoRA/QLoRA、数据构造——知道「什么时候不该微调」比会微调更重要
  • P3 · 训练与论文：预训练、分布式训练、论文复现——明确放弃，这不是应用工程师的战场
建议目标岗位：AI 应用开发工程师 / LLM 应用工程师 / AI 平台工程师 / 端智能工程师，而不是算法工程师。

三、四阶段路线图（点击展开每个阶段）

每个阶段都有明确的「产出物」，没有产出物就意味着这个阶段没完成。

M1–M3

阶段一 · 打地基：Python 生态 + 深度学习通识

目标：能读懂代码、跑通训练、说清 Transformer 在干什么 ▶

核心内容

  • Python 工程化（2 周）：类型注解、async/await、uv/poetry、pytest、ruff、dataclass/pydantic
  • PyTorch 基础（3 周）：张量、autograd、Dataset/DataLoader、标准训练循环
  • 深度学习通识（4 周）：MLP/CNN/RNN、损失函数、优化器、过拟合与正则化、评估指标
  • Transformer（3 周）：Self-Attention、位置编码、Tokenizer、Embedding、BERT vs GPT
  • 推理基础（1 周）：KV Cache、batch、量化概念、GPU/显存直觉

学习策略

  • 李沐的课不要全刷，只看：线性回归→softmax→CNN→注意力机制→Transformer 相关章节
  • 数学不推导，只求「看见公式知道在说什么」
  • 每个概念配一段 20 行代码验证，别只看视频
  • 用你熟悉的 Kotlin/Java 做类比记忆（如 DataLoader ≈ PagingSource）
  • 每周至少 1 篇笔记发到博客/知乎，形成外部约束
阶段产出：① 用 PyTorch 从零实现一个字符级 mini-GPT；② 手写 Multi-Head Attention 并与 nn.MultiheadAttention 对拍；③ GitHub 上有 3 篇以上学习笔记。
M4–M6

阶段二 · 主战场：LLM 应用开发核心

目标：能独立交付一个生产可用的 RAG 系统 ▶

核心内容

  • Prompt 工程（1 周）：零样本/少样本、CoT、系统提示、JSON Mode / 结构化输出、防注入
  • LLM API 工程（2 周）：OpenAI / Anthropic / 国产模型 SDK、流式输出、Token 计费、重试限流、超时降级
  • RAG 全链路（4 周）：文档解析 → Chunking → Embedding → 向量库（pgvector / Milvus / Chroma）→ 混合检索 → Rerank → Query 改写 / HyDE
  • 上下文工程（1 周）：上下文窗口管理、压缩、缓存（Prompt Caching）
  • 微调（3 周）：LoRA/QLoRA、PEFT、数据集构造、trl；重点理解什么时候不该微调
  • 后端基础（穿插）：FastAPI、异步接口、SSE 流式推流

学习策略

  • 吴恩达的 short course 每门只有 1–1.5 小时，性价比最高，优先全部刷完
  • LangChain 学概念即可，不要陷入框架细节——生产里更多是自己写编排
  • RAG 必须亲手做一遍「效果很差 → 定位问题 → 逐个优化」的完整过程，这就是经验
  • 建一个自己的评测集（50–100 条问答），没有评测集的优化都是玄学
  • 对比不同 Chunk 策略、不同 Embedding 模型的召回率，把结果写成表格
阶段产出：① 企业知识库 RAG 问答系统（FastAPI + pgvector + 流式前端 + 引用溯源）；② 一份 RAG 优化对照实验报告；③ 一次 LoRA 微调实验及效果对比。
M7–M9

阶段三 · 进阶：Agent 工程化与 AI 系统质量

目标：从「会调 API」升级为「能设计可靠 AI 系统」 ▶

核心内容

  • Agent 基础（2 周）：ReAct、Tool Use / Function Calling、规划、短期/长期记忆
  • 编排框架（3 周）：LangGraph（图/状态机，重点）、LlamaIndex、smolagents；多 Agent 协作
  • MCP 协议（1.5 周）：Server / Client 开发、工具生态、与你现有服务打通
  • 服务化（2 周）：FastAPI 工程结构、Celery 异步任务、Docker、SSE/WebSocket 流式
  • AI 系统质量（3 周）：离线评测集、RAGAS、Langfuse / LangSmith 可观测、成本与延迟监控、Guardrails 与安全
  • 部署（1.5 周）：vLLM / Ollama 本地推理、模型路由与降级

学习策略

  • 这一阶段决定了你能拿 P6/P7 还是 P5 的 offer——工程化与可靠性是分水岭
  • 把 Agent 当成「分布式系统」来学，你已有的架构经验可以大量复用
  • 一定要接入可观测工具，能看到 Trace 才算真正理解 Agent 在干什么
  • 研究真实失败案例：循环调用、幻觉、工具选错、上下文爆炸
  • 主动给开源项目提 issue/PR，这是简历上很强的信号
阶段产出：① 一个多 Agent 工作流系统（带完整 Trace 与评测集）；② 自建 MCP Server 并接入客户端；③ 一篇《LLM 应用可靠性设计》深度文章。
M10–M12

阶段四 · 打出王牌：端侧 AI + 作品集与求职

目标：成为「懂 AI 应用的客户端专家」——市场上极稀缺的复合型 ▶

核心内容

  • Android AI 栈（3 周）：LiteRT（原 TFLite）、MediaPipe LLM Inference API、Gemini Nano / Gemma 接入
  • 端侧 LLM 部署（3 周）：llama.cpp Android、MLC-LLM、ExecuTorch；GGUF、INT8/INT4 量化、LoRA 合并
  • 性能优化（2 周）：NNAPI / GPU Delegate、NPU 加速、内存峰值、首 Token 延迟、KV Cache 复用
  • 端云协同（2 周）：本地小模型 + 云端大模型的路由策略、离线降级、隐私合规
  • 求职冲刺（2 周）：简历重构、作品集打磨、模拟面试

学习策略

  • 这是你唯一能碾压纯 AI 背景候选人的赛道，务必做深做透
  • 2026 年旗舰机普遍支持本地运行 7B 以下模型，端侧 AI 正从探索走向落地
  • 做出可量化的性能指标：机型 × 量化方案 × 首 Token 延迟 × 内存占用对照表
  • 做成一个真正能用的 App 并开源，比任何证书都有说服力
  • 同时准备 Java 生态方案（Spring AI / LangChain4j）作为备选叙事
阶段产出：① Android 离线 AI 助手 App（端侧 2B–3B 模型 + 云端可选增强），开源并附性能对照表；② 简历与作品集网站；③ 完成 10+ 场面试。

七、求职与简历策略

转型者最大的误区是把简历写成「新手 AI 工程师」，而正确写法是「懂 AI 应用的资深工程专家」。

1

重构叙事，而不是抹掉过去

简历主线写：「5 年客户端工程经验 + 系统化 AI 应用工程能力」，强调架构、性能、稳定性、产品化交付，而不是「自学 AI 半年」。

2

用项目说话，不写「熟悉」

把「熟悉 RAG」改成「设计并实现企业知识库 RAG 系统，通过混合检索 + Rerank 将召回率从 62% 提升至 89%」。数字是最强的证据。

3

关键词要对上 JD

必含：RAG、Agent、Function Calling、LangGraph、Prompt Engineering、模型评测、推理优化、向量数据库、FastAPI、端侧推理、量化。

4

优先投这三类岗位

① AI 应用/平台工程师；② 端智能工程师（你的蓝海）；③ 有移动端 AI 场景的业务团队。避免硬碰算法岗。

5

准备系统设计题

高频题：「设计一个企业知识库问答系统」「设计一个可靠的多 Agent 系统」「如何在手机上跑一个 3B 模型」。这些正是你项目的原型。

6

内部转岗优先于外部跳槽

若现公司有 AI 相关业务，先争取参与或借调。在职转型的试错成本最低，且保住了你的资深职级与薪资基数。

风险提示：2026 年 AI 应用岗位竞争已明显加剧，初级岗位收缩快，但「能落地、能工程化、懂业务」的中高级工程师依然稀缺。
因此这份规划的核心不是学得更多，而是学得更「能交付」——每一个知识点都要落到可以演示、可以量化、可以写进简历的产出上。
